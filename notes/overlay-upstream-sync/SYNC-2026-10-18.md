Upstream had merged most of what this project submitted (#16250 the KN7000 driver, #16394 the
on-chip DMA and SP7001 support, #16413–#16416 the floppy software lists, and others), so the
overlay was brought back in line with `upstream/master` before looking for what is still
unsubmitted. `UNSUBMITTED-2026-10-18.md` in this directory is that inventory.

## Driver changes made during the resync

1. **Floppy DMA.** Upstream #16394 models MN10300 DMA channel 0 (registers `0x32000800..0x3200080C`).
   Both the KN7000 (941: `0x484009BE`) and the KN6000 (linear image `0x110DF0`) program it for
   the sector-data phase, with the FDC.DACK slot `0x98010000` at one end. The overlay used to raise
   INTC group 0x18 per DRQ instead, which moved no sector data. The core now has the channel, the
   FDC's DRQ drives it and its terminal count goes back to the FDC.
2. **Software lists.** `kn7000_flop` on kn7000/kn2400's parent config, replaced by `kn6000_flop` on
   kn6000/kn6500, removed on kn2400 (no list yet).
3. **DMA count + 1, end interrupt, TC from GPIO.** Upstream's channel moves count + 2 and pulses
   TC; that overruns every KN6000 sector by one byte. The overlay's moves count + 1, raises INTC
   group 0x0F and leaves TC to GPIO 0x36008004 bit 4 (`c50dc00`). A deliberate divergence from
   #16394, to be offered upstream.
4. **Drive INDEX on IRQ7 (group 0x1E).** Not in upstream. The firmware's disk-presence check
   needs it to see a disk inserted at run time — see `kn7000.cpp` `fdd_index_poll` and
   `notes/kn6000-feature-presentation.md`.

## Upstream fixes the overlay had lost

The inventory (`UNSUBMITTED-2026-10-18.md`, Table B) found five upstream fixes missing from the overlay
by accident. The three-way merges could not see them: they landed upstream before the old
`SYNCED-AT`, in files the overlay had already forked, so the merge base contained them and the
overlay's older text looked like a deliberate change. All five are ported:

| inventory | file                   | fix                                                                                                                                      |
|-----------|------------------------|------------------------------------------------------------------------------------------------------------------------------------------|
| B.3       | `sharc/sharcdrc.cpp`   | `UML_SETFMOD(ROUND_ROUND)` at the DRC entry point (fac12419a82, the x64 rounding fix)                                                    |
| B.11      | `kn_cpanel.cpp/.h`     | `panel_queue()` returns false when full; the scan keeps its old state, so a dropped change is resent (a lost release left a button held) |
| B.12      | `kn7000_cpanel.cpp/.h` | `m_cpc_leds` sized 256: CPC registers 0xE0-0xFF index LEDs up to 255, past the old 64                                                    |
| B.13      | `kn7000_cpanel.cpp`    | ORGANIST (`CPL_SEG1` 0x02) and 60s & 70s (`CPL_SEG2` 0x40) were `IPT_UNUSED`, so the layout's buttons did nothing                        |
| B.17      | `video/sed1330.cpp`    | retired in favour of upstream's, which tests the cliprect in text and graphics drawing                                                   |

B.4 (SHARC `offs_t`, `has_single_bit`, `UIREG`/`std::rotl`) was checked and is cosmetic: the old
code already cast to `uint32_t` before shifting. It stays unported.

## Verification

Every build: `./build.sh` with 0 `error:` lines, `kn7000 -validate` exit 0 with no output, and the
retired files confirmed rebuilt from upstream (`spi_sdcard.o`, `sed1330.o` newer than the retirement).
All four floppy software lists verify from the published folder (`-verifysoftlist`: kn6000_flop 21/21,
kn7000_flop 6/6, kn5000_flop 14/14, wsa1_flop 9/9).

**Gate attribution.** `tools/gate.sh` failed three checks on the first resync build, so the same
gate ran on four binaries, each from its own folder with the same NVRAM snapshot (MAME rewrites

- the **kn7000 oracle** and the **kn6000 liveness** failures predate the resync (O fails the same way);
