## Step 1 — port #16016 into the overlay's SHARC copies  ✅ done

Six lines, mechanical, restoring what upstream already merged as
`666893f2eb9 cpu/sharc: Fixed off-by-one errors in circular buffer wrapping. (#16016)`:

- `src/devices/cpu/sharc/sharcops.hxx:38` — `PM_REG_I(x) > …` → `>=`
- `src/devices/cpu/sharc/sharcops.hxx:53` — `DM_REG_I(x) > …` → `>=`
- `src/devices/cpu/sharc/sharcdrc.cpp:1795,1816` — `COND_LE` → `COND_L`
- `src/devices/cpu/sharc/sharcdrc.cpp:1801,1822` — `COND_G` → `COND_GE`

plus upstream's explanatory comment, and the false comment at `build.sh:106-107` in the same
commit ("Only sharc.h/sharc.cpp are overlaid; the rest of the SHARC core is stock" — the next
three lines symlink `sharcops.hxx`, `sharcdrc.cpp` and `sharcfe.cpp`; that comment is what hid
this for as long as it hid).

**Known consequence:** DSP behaviour moves by one element at the wrap boundary. Any LLE result
calibrated against the old boundary may shift. Upstream's position is that the old boundary was
wrong — the buffer occupies `[B, B+L)`, so an index reaching `B+L` must wrap.

## Step 2 — fix the `wsa1` registration  ✅ done

`build.sh:332` tests for one system and inserts two:

    if '\nwsa1r\n' not in s:
        s = s.replace(anchor, anchor + '\n@source:matsushita/wsa1.cpp\nwsa1r\nwsa1\n', 1)

Since #16204 merged, upstream's `mame.lst:27025` already contains `wsa1r`, so the guard is
satisfied and the block is skipped whole — `wsa1` is never inserted. `wsa1.cpp:4342-4343`
declares both systems; `-listfull` on the 2026-09-22 binary shows `wsa1r` and no `wsa1`.

Fix applied: the two systems are now guarded **separately**, as the `kn6000` loop above them
already is. The first guard still creates the `@source:` header and `wsa1r` when a base lacks
them; a second guard inserts `wsa1` under its parent wherever `wsa1r` ended up.

**Result, 2026-09-26.** Dry-run against upstream's own `mame.lst` first, which produced
`wsa1r` / `wsa1` under the existing header. Rebuilt: **0 errors**, `mame.lst:27028-27029` now
carries both, `-listfull` lists `wsa1  "SX-WSA1"` alongside `wsa1r`, `-validate` exit 0 with no
output, and **both boot** — wsa1 54%, wsa1r 48%, each exit 0. Published.

removed its `#include`, replacing the generated table with a walk of the sub-CPU's multisample

error, not a silent behaviour change", was disproven by the step 5 rebuild, which compiled
cleanly without the file.

Removed, along with the **four comments** that still described the superseded mechanism:
`kn5000_tonegen.cpp:35-37` ("generated from notes/data/... by tools/gen_kn5000_pitch_trim.py"),
`:1762` ("kn5000_pitch_trim::TABLE", when the code reads `m_pitch_c`), `:1845`
("kn5000_pitch_trim.hxx, generated") and `kn5000_tonegen.h:395` ("the generated
kn5000_pitch_trim.hxx").

`tools/gen_kn5000_pitch_trim.py` is **kept**: its `--check` mode is still the cross-check of the
ROM walk against `notes/data/kn5000-pitch-trim-table.tsv`, and
`notes/FINDINGS-kn5000-pitch-trim-baked-in.md:28` relies on it.

**Result, 2026-09-26.** `bash -n` clean, no reference to the deleted header left anywhere in
`src/` or `build.sh`, rebuild **0 errors**, `-validate` exit 0 with no output, kn5000 96% and

## Step 4 — the prescaler divergence  ⛔ Felipe's decision, not to be guessed

`tmp95c061.cpp:864-867` carries `3/5/7/11`; upstream restored `7/9/11/15` in #16255 after the
user-confirmed ngp/ngpc music regression. The overlay's `tlcs900.h` has no
`execute_clocks_to_cycles()` override, so its counter runs at fc and every TMP95C061 8-bit timer
runs sixteen times fast. This reaches **wsa1/wsa1r**; kn5000 and kn7000 are unaffected.

1. **Take upstream's values** — overlay matches MAME, wsa1/wsa1r timers correct.
2. **Keep them, and document why** — if the WSA1 work depends on them.
3. **Take upstream's values *and* the fc/2 override** — un-park the parked branch inside the
   overlay only: same timer rates, halved CPU.

Whichever is chosen, the two documents still arguing "ngp is evidence *for* the change"
(`tmp95c061.cpp:857-862` and `notes/WSA1-EMULATION-DISASM-GAPS.md:1409-1416`) have to change.
