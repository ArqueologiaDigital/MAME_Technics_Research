### Committed vs generated — the repo's actual policy

- **ROM bytes are never committed raw** — `baserom/*.rom` and `build/` are ignored as "derived data, regenerated by make" (.gitignore:1-4).
- **Generated *listings* ARE committed when small/curated**: `disasm/table_directory.asm` is simultaneously a Makefile target (Makefile:109-112) and a tracked file — the exact precedent for the DSP tree. Only the ~30 MB `program.asm`/`program_named.asm` are ignored (.gitignore:8-11).
- **Generated symbol tables are committed** (`kn7000.sym` is a `make symbols` output yet tracked), and commits are per-discovery with the pattern `symbols: <what was named> ; verify 100%` (see `git log`: e.g. commits `907d006`, `df55b31`).

### Symbol-file format

- `kn7000.sym` / `kn7000_manual.sym`: one entry per line, **`0xADDR  Name<TAB>; comment`**; `;` starts comments both full-line and trailing (kn7000_manual.sym:13-24 shows the style, including section-header comment blocks like `; ---- Control-panel serial protocol ... ----`).
- Consumer: `tools/disasm_functions.py:21-30` — regex `0x([0-9A-Fa-f]+)\s+(\S+)`, and it **skips any address `< 0x48400000`** (line 28). So SHARC PM/DM addresses (0x8000 etc.) can NOT be dropped into these files; a DSP-specific sym file with its own consumer is required (and is safe — the MN10300 tools will ignore it if kept separate).

## 2. Proposed DSP tree in `kn7000_disassembly`

The DSP program is 80 host-download records at program-ROM file offsets **0x2BCEC4–0x2CE68D (CPU 0x486BCEC4–0x486CE68D, 71,625 bytes)**; record format, kernel/probe/effect roles and the PM 6-byte→8-byte-LE repack recipe are already documented in `/home/fsanches/compartilhado/kn7000_mame/notes/dsp-host-interface.md` §2 (interpreter fn 0x48407BD8; kernel record @0x486BD9A8; 4 probe records @0x486BCEC4/0x486BD17D/0x486BD436/0x486BD6EF). The extraction scripts from that recon were scratchpad throwaways (only `sharc_pm8000.bin` etc. survive) — the tool must be (re)written, which is fine: the note itself says "productize into `kn7000_disassembly/tools/`".

### Layout (follows the repo's src-vs-tools-vs-disasm split)

```
kn7000_disassembly/
├── dsp/                          # NEW — curated (hand-written) DSP knowledge, all committed
│   ├── README.md                 # record-pool format, host-port protocol summary, provenance
│   │                             #   (cite interpreter 0x48407BD8, ports 0x98000000/0x9C000000,
│   │                             #    kn7000_mame/notes/dsp-host-interface.md)
│   ├── records.tsv               # manifest: idx  rom_off  cpu_addr  size  blocks  role  name  notes
│   │                             #   (role: kernel|probe|effect; name column hand-curated as
│   │                             #    effect identities are recovered via the 146-entry table 0x500066E0)
│   └── sym/                      # hand-curated SHARC symbols/comments, same line format as
│       ├── kernel.sym            #   kn7000_manual.sym but with a space prefix:
│       ├── rec05.sym …           #   "pm:0x8004  KernelIdle    ; vector-table IDLE"
│                                 #   "dm:0x9800  ParamBlock    ; per-effect-unit, stride 0x50"
│                                 #   one file per record because all effects reload at PM 0x8400
│                                 #   (same numeric addr, different meaning per record)
├── disasm/dsp/                   # NEW — GENERATED **and COMMITTED** listings (table_directory.asm precedent)
│   ├── index.asm                 # rendered manifest of all 80 records (like table_directory.asm)
│   ├── rec04_kernel_0x486BD9A8.asm
│   ├── rec00_probe_0x486BCEC4.asm …
│   └── rec05_effect_0x486BDBAx.asm … (79 more; ~6,499 PM words + 5,775 DM entries total ⇒ well under 1 MB)
├── tools/gen_dsp_records.py      # NEW — pool walker: parse records from baserom/kn7000_program.rom,
│                                 #   repack PM (3×BE u16 → 64-bit LE slot), drive `unidasm -arch sharc
│                                 #   -basepc <PM target>`, dump DM blocks as typed word tables,
│                                 #   merge labels/comments from dsp/sym/*.sym and headers from records.tsv
└── build/dsp/                    # raw per-block extracts (recNN_pm_8400.bin …) — already git-ignored via /build/
```

Filenames are **stable by index + pool CPU address** (`recNN_role_0xADDR.asm`); human-readable effect names go in the file *header comment* (from `records.tsv`), not the filename, so later identification of an effect doesn't rename files and churn history.

Each listing's format mirrors the committed samples: a `;` header block (like `disasm/program_entry.asm:1-4` / `disasm/table_directory.asm:1-3`) stating record index, ROM offset/CPU addr, block table, then per-block `label:` + unidasm output (like `disasm/program_named_sample.asm`). Semantic commentary lives in `dsp/sym/*.sym` (merged as labels + trailing `;` comments) plus free-form paragraphs in the header taken from `records.tsv` notes — so regeneration never loses annotations.

### Makefile rule (matches existing style, Makefile:89-112)

```make
# ---- SHARC effects-DSP record pool (IC306 ADSP-21065L, host-booted) ---------
# 80 download records embedded in the program image @0x2BCEC4..0x2CE68D.
DSP_POOL := 0x2BCEC4 0x2CE68D

disasm-dsp: baserom/kn7000_program.rom tools/gen_dsp_records.py \
            dsp/records.tsv $(wildcard dsp/sym/*.sym)
	@mkdir -p disasm/dsp build/dsp
	@echo "==> extracting + disassembling SHARC record pool ($(DSP_POOL)) with unidasm"
	$(PYTHON) tools/gen_dsp_records.py --rom $< --pool $(DSP_POOL) \
	    --unidasm $(UNIDASM) --manifest dsp/records.tsv --symdir dsp/sym \
	    --bindir build/dsp --out disasm/dsp
	@echo "wrote disasm/dsp/"

disasm: … disasm-dsp        # add to the existing aggregate target (Makefile:90)
```

`.gitignore` needs **no change** (`/build/` already covers `build/dsp/`; `disasm/dsp/*.asm` deliberately not ignored). Two complementary tie-ins, both in existing conventions: add the interpreter/driver functions (`0x48407BD8` record downloader, `0x484050B8` PM-word writer, `0x48405086` DspAddrWrite, …) to `kn7000_manual.sym` under a `; ---- Effects DSP (ADSP-21065L host port) ----` section; and label the pool region in `src/program.s` (`DspRecordPool:` above the corresponding `.incbin_range 0x2bcec4, 0x2ce68e`) — neither affects `make verify`.

## 3. Cross-model placement

- **KN5000 (`/home/fsanches/compartilhado/kn5000-roms-disasm/`)**: its convention is **top-level per-processor directories** — `subcpu/boot/` + `v142/subcpu/` (TLCS-900 sub-CPU: `.s` + `.ld` + `includes/*.bin`, Makefile:605-628) and `hdae5000/` (expansion board), with symbols in `symbols/<unit>_symbols_reference.txt` — note the **reversed column order** there: `NAME 0xADDR` (symbols/subcpu_symbols_reference.txt:2). So KN5000 DSP/effect code would go in a new top-level `dsp/` with `symbols/dsp_symbols_reference.txt`. Whether the KN5000's effects DSP is host-booted with an embedded program (and what the chip is) is **not established** — the repo only has `DSP_`/`DSP2_` naming prefixes for "DSP hardware control" (CLAUDE.md:624); no SHARC/21065 evidence found in that repo.
- **KN6000/KN6500**: **no disassembly repo exists** (`/home/fsanches/compartilhado/KN6000/` is only service manuals + downloads; no `*disasm*` dir matches). The KN6500 service manual **does list the same S21065LKS240 SHARC** (scratchpad kn6500_sm.txt lines 9012, 22173), so when a KN6000 disassembly repo is created it should clone the `kn7000_disassembly` layout including `dsp/` + `disasm/dsp/`. For that reason `tools/gen_dsp_records.py` should take the pool bounds/ROM/base as CLI parameters (as sketched above), not hardcoded KN7000 constants, so the identical tool serves KN6000/KN6500 (and KN2400/2600 if they carry the same pool).

## 4. Git hygiene

- **Commit**: `tools/gen_dsp_records.py`, `dsp/README.md`, `dsp/records.tsv`, `dsp/sym/*.sym`, and the **generated `disasm/dsp/*.asm` listings**. This is exactly the `disasm/table_directory.asm` precedent (generated-and-tracked), the total is small (~71.6 KB of pool ⇒ listings well under 1 MB, vs the 30 MB program.asm that IS ignored), and it satisfies the requirement of *versioned commented* disassembly: annotation progress shows up as reviewable diffs of the listings driven by edits to `dsp/sym/` + `records.tsv`.
- **Do not commit**: raw `build/dsp/*.bin` record extracts — verbatim ROM-derived bytes, matching the repo's "derived data … never committed" rule (.gitignore:1-3). Anyone can regenerate them with `make disasm-dsp` from the disk-extraction chain.
- **Determinism**: the generator must be byte-stable (fixed ordering, no timestamps/absolute paths in output) so `make disasm-dsp && git diff --exit-code disasm/dsp` doubles as a drift check; note the unidasm dependency in the listing headers (unidasm output format changes with MAME versions — if it ever drifts, that's one mechanical commit touching all listings, clearly separated from annotation commits).
- **Commit-message convention**: mirror the existing per-discovery style (`git log`: `symbols: …; verify 100%`) as `dsp: name recNN <effect> …` — one record/subsystem per commit; `make verify` is untouched by this tree but stating it keeps the log uniform.
