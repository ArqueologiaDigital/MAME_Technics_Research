KN5000 IC311 effects DSP (NEC uPD6383GF-3BA). Date: 2026-07-22.
Tool: `tools/kn5000_dsp_hi12.py` (imports `kn5000_dsp_chorus`, `kn5000_dsp_params`;
**neither is edited**, and **no earlier note is edited** — corrections are collected in §7).

Follows `kn5000-dsp-axes.md` §10, which ranked "decode `hi12`, not `lo12`" and "pin the data
pointer's origin" as the two highest-value unknowns. This note does the first and **rules the
second out on static evidence**.

Claims are tagged **MEASURED**, **PROVEN BY CONSTRUCTION**, **INFERRED** or **SPECULATIVE**.

that was measured and failed.

## Headline

1. **★★★ `hi12` IS NOT AN OPCODE. IT IS A HORIZONTAL MICROWORD OF INDEPENDENT ENABLE BITS.**
   The decisive measurement is the **terminator residue**: nine distinct `hi12` values have
   mean normalised position **exactly 1.000**, all nine carry **bit 10**, they number
   **exactly 38 — one per image, with zero occurrences anywhere else in 2974 words** — and when
   bit 10 is removed, **all nine residues are themselves ordinary `hi12` values that occur as
   working instructions elsewhere** (`612 = END|212`, `604 = END|204`, `602 = END|202`,
   `504 = END|104`, `42C = END|02C`, `428 = END|028`, `424`, `420`, `400 = END alone`). An
   enumerated opcode field has no reason to place nine halt codes at a constant offset `0x400`
   from nine ordinary codes. **MEASURED** (§3).
2. **★★★ bit 10 (with bit 11 clear) = END OF PROGRAM**, and the last instruction **still does its
   work**. This retires a landmark that has been recognised since `-encoding.md` but never
   attributed to a field: the terminator was identified by `class4==1 && addr8 ∈ {0x0E,0x0F}`,
   which is the *unit index*, not the halt. The halt is bit 10 of `hi12`. **MEASURED** (§3).
3. **★★★ bit 4 = WRITE THE ACCUMULATOR TO `mem[ptr]`.** Two investigations that were not looking
   at bit 4 supply the labels, and both land the same way: `0x202` = `mac` (no write) vs
   `0x212` = `mulst` (writes) — uniquely determined by the 19.7 M-assignment search — and
   `0x082` = LFO source *read* vs `0x092` = phase accumulator, which must write the phase back.
   `0x212 = 0x202 | bit4` and `0x092 = 0x082 | bit4`. The **control** is absence, and it passes:
   excluding the 38 terminators, **0 of 410** words in the classes whose `addr8` provably is not
   a pointer (1, 3, 5, 6, 8) carry bit 4, against 94 expected. **MEASURED** (§4).
4. **★★ IT BREAKS A 2-PERMUTATION `-semantics.md` LEFT OPEN.** The reverb diffuser's
   `000.2.00.419` / `012.2.00.680` pair was "one is `d_in ← x + t`, the other is `y ← d_out − t`,
   CONSTRAINED to a 2-permutation". Only `0x012` carries bit 4, so **`012.2.00.680` is the write**
   — and it sits immediately before `880.1.20.655`, the DRAM-**write** half of the bracket, which
   is an independent positional corroboration nothing in the bit-4 argument used. **MEASURED** (§4.4).
5. **★★ AND IT FAILS TO BREAK THE BIQUAD'S, WHICH I REPORT AS PROMINENTLY.** The biquad's
   `[5] 102.2.FF.687` / `[8] 000.2.03.647` are also two writes, and **neither carries bit 4**.
   Under bit 4 = store that is a contradiction unless the *latch* writeback is a different
   mechanism from the accumulator store — which is what `-INDEX.md` already records (`lo12 ∈
   {0x647, 0x687}` = "biquad non-multiply steps"). Consistent, but this is a **repair, not a
   prediction**, and I flag it (§4.5).
6. **★★ THE PROBLEM REALLY IS ~54 OPERATIONS, NOT 655 WORDS — AND IT IS SMALLER STILL.** The
   brief's arithmetic is confirmed exactly: **54 distinct `hi12` values, 1.32 % of the 12-bit
   space.** But the decomposition shrinks it further: 54 values are generated by **12 bits**,
   and three bit positions (11, 10, 4) now carry meanings, so **the 54-value alphabet is not the
   unit of work — the twelve bits are** (§2).
7. **★ THE POINTER ORIGIN CANNOT BE PINNED FROM THE ROM. Four searches, all negative.** No
   class-subset rule, no wrap modulus ≤ 4096, and no `hi12`-bit gate makes any image's pointer
   return to where it started (net delta per image ranges `−87 … +1149`, zero in **0 of 38**).
   The proven `ldptr` form occurs **zero** times in the 38 bodies — it is a *host-poke* word.
   And the biquad's "channel bases `0x40`/`0x54`" are themselves origin-relative and are
   therefore **not** an independent anchor, which is a correction (§5).
8. **★ COVERAGE, HONESTLY: 17.5 % → 18.3 %** (520 → 545 of 2974). The gain is **+0.8 points**.
   The 680 words carrying bit 4 are **not** counted as decoded: one bit of a 36-bit word is not a
   decode, and refusing that over-claim is the same refusal `-axes.md` §6.1 made about the
   47 % figure (§6).

### 2.2 ★ THE CLOSURE TEST (**MEASURED**), stated before it was run

> **Prediction.** An *enumerated* opcode field has no reason to contain many pairs of values one
> bit apart. A *fielded* / horizontal encoding is nearly forced to: toggling one enable gives
> another legal word. So count Hamming-distance-1 pairs among the 54 observed values, against a
> null that holds the popcount profile fixed (so the score cannot come from the values merely
> being sparse or low-weight). **This can fail.**

```
   observed HD-1 pairs among the 54 values : 77
   null (same popcount profile, 2000 draws): 43.39 +/- 4.26
   ->  z = +7.9
```

Per-bit, the pairs are spread across **every one of the twelve bit positions** (bit 7: 11 pairs,
bits 2/3/4/10: 9 each, bit 11: 1). A single hot sub-field would have concentrated them.

### 2.3 Sub-field completeness (**MEASURED**)

If a run of bits is a field, some prefix should exercise all of its values.

```
   bits[3:1] under prefix 0x02_ : 020 022 024 026 028 02A 02C 02E   -> 8/8, bit0 always 0
   bits[9:8] on the ..02 base   : 002 102 202 302                   -> 4/4
   bits[9:8] on the ..82 base   : 082 182 282                       -> 3/4  (382 unused)
```

Eight of eight and four of four are not coincidences in a set that occupies 1.3 % of the space.

### 2.4 bit 11 is an ESCAPE, not a modifier (**MEASURED**)

A modifier leaves a legal word when removed. Bit 11 does not:

```
   800 -> 000  in vocabulary: True        880 -> 080  False
   801 -> 001  False                      900 -> 100  False
   804 -> 004  False                      A00 -> 200  False
   80A -> 00A  False                      C40 -> 440  False
   80B -> 00B  False
   residue-in-vocabulary: 1/9
```

Contrast bit 4, where the same test gives **9/9 among the values whose base is observed at all**
(§4.1), and bit 10, where it gives **9/9** (§3.2). **INFERRED: bit 11 selects a second word
format** in which bits [10:0] mean something else. The corroborating control is `0xC40`: it
carries bit 10, yet its mean position is **0.570**, not 1.000, and it appears in classes 0/1/2/3/5
— inside the bit-11 format, bit 10 is not the end marker.

### 2.5 The brief's labelled signal (**MEASURED**)

The brief asked that a correct decomposition place `0x092`/`0x094` near each other and separate
`0x212` from `0x102`. It does:

* `0x092` and `0x094` are Hamming distance 2 and **both are `0x090 | x`**. `0x082` (LFO source
  read) is `0x090` with bit 4 cleared. The whole LFO/phase machinery — `082 090 092 094 09A` —
  is one contiguous block: **bit 7 set, bits 8 and 9 clear**.
* `0x212` (store) and `0x102` (multiply) differ in bit 4 — the store — and in bit 9 vs bit 8.

## 3. bit 10 = END OF PROGRAM

### 3.1 The prediction and its control (**MEASURED**)

> **Prediction, before the check.** Nine `hi12` values have mean normalised position exactly
> 1.000 and all carry bit 10. A word carries bit 10 (bit 11 clear) **if and only if** it is the
> terminator. The load-bearing half is the *only if*: **not one such word may appear anywhere
> else** in the 2974.

```
   words with bit10 set and bit11 clear : 38
   images in the corpus                 : 38
   of those, NOT (class 1 & addr8 in {0E,0F} & last word of the image) : 0
```

Exactly one per image, zero elsewhere. **The prediction holds with no exceptions.**

### 3.2 ★ The residue-closure test (**MEASURED**) — the decisive one

```
   terminator 400 x8  -> residue 000  ordinary hi12: True  (x809 elsewhere)
   terminator 420 x2  -> residue 020  True (x10)      terminator 602 x3 -> 202  True (x289)
   terminator 424 x2  -> residue 024  True (x2)       terminator 604 x4 -> 204  True (x54)
   terminator 428 x12 -> residue 028  True (x22)      terminator 612 x5 -> 212  True (x352)
   terminator 42C x1  -> residue 02C  True (x1)       terminator 504 x1 -> 104  True (x142)
   residues that are ordinary hi12 values : 9/9
```

Tight null: the residue is 10 bits, so a random bit-10-set/bit-11-clear `hi12` has residue uniform
over 1024; 36 of the 54 observed values are below `0x400`; chance per residue `36/1024 = 0.0352`;
all nine `= 8.2e-14`.

**The caveat, because it cuts against me**: the residues are the corpus's *common* ops, so they
are not uniform draws either. The argument that survives that objection is qualitative and is the
one I rely on: **an enumerated opcode has no reason to place nine halt codes at a constant offset
`0x400` from nine ordinary codes at all.**

> **ASSIGNED (MEASURED): `hi12` bit 10, with bit 11 clear, is END OF PROGRAM, and it is a
> MODIFIER — the terminating instruction still performs the operation named by the rest of the
> word.** `612.1.0E.000` = "mac, store, and halt".

## 4. bit 4 = WRITE THE ACCUMULATOR TO `mem[ptr]`

### 4.1 The `+bit4` pairs (**MEASURED**)

```
   010 (x10)  = 000 (x809) + bit4        192 (x43)  = 182 (x69)  + bit4
   012 (x125) = 002 (x11)  + bit4        212 (x352) = 202 (x289) + bit4
   050 (x2)   = 040 (x53)  + bit4        292 (x10)  = 282 (x13)  + bit4
   092 (x77)  = 082 (x64)  + bit4        612 (x5)   = 602 (x3)   + bit4
   112 (x4)   = 102 (x190) + bit4
```

`612 = 602 | bit4` **and** `612 = 0x400 | 212`: the two independent decompositions of §3 and §4
agree on the same word.

Five bit-4 values have an unobserved base (`018 090 094 09A 29A` → `008 080 084 08A 28A`). That
is a **falsifiable prediction**: those five are legal encodings this corpus simply never needs,
and any further ROM that contains one confirms it.

### 4.3 ★ THE CONTROL: bit 4 must predict ABSENCE (**MEASURED**)

> **Prediction, before the check.** A store to `mem[ptr]` is impossible where `addr8` is provably
> not a pointer. Class 6's `addr8` is the table-lookup selector; class 1's is a DRAM bracket code
> or the unit index; class 8's `addr8 = 0x16` is unknown but never a cell; class 3 is the
> modulation-offset form. **Those classes must carry no bit 4 at all.**

```
   class distribution, bit4 SET   : {0:2, 1:5, 2:351, 4:53, A:269}
   class distribution, bit4 CLEAR : {0:99, 1:317, 2:1199, 3:30, 5:1, 6:53, 8:42, A:553}

   excluding the 38 terminators, bit4 words in classes {1,3,5,6,8}:
        0 of 410      (expected under independence: 94)
```

**Zero of 410.** The control passes and it could easily have failed.

**FLAGGED EXCEPTION**: the five `612.1.0E/0F.000` terminators do carry bit 4 while their `addr8`
is the unit index. Either a terminator repurposes `addr8`, or the halting store goes somewhere
else. **Reported, not explained** — it is the only blemish on an otherwise clean control, and it
is exactly the kind of thing this project has had to retract when it was swept up.

### 4.4 ★ An ambiguity it BREAKS (**MEASURED**)

`-semantics.md` §6 left the reverb diffuser's pair CONSTRAINED to a 2-permutation. bit 4 breaks it,
and position corroborates independently:

```
   [19] 880.1.60.2D4   bit4=clear      <- DRAM bracket, read half
   [20] 104.2.00.000   bit4=clear
   [21] 000.2.00.419   bit4=clear
   [22] 012.2.00.680   bit4=SET        <- the write
   [23] 880.1.20.655   bit4=clear      <- DRAM bracket, WRITE half
   [24] 102.A.00.64B   bit4=clear
   [25] 000.2.00.000   [26] 000.2.00.000
```

> **ASSIGNED (MEASURED): `012.2.00.680` = `d_in ← x + t`** (the write into the delay line);
> **`000.2.00.419` = `y ← d_out − t`.** Nine of each in algo 16, one per diffuser. The write word
> is immediately before the DRAM-write bracket half — a positional fact the bit-4 argument did not
> use.

### 4.5 ★ An ambiguity it DOES NOT break (**MEASURED, reported as prominently**)

The biquad's `[5] 102.2.FF.687` and `[8] 000.2.03.647` are also a 2-permutation of two writes
(`mem[S3] ← latch B` / `mem[S1] ← latch A`), and **neither carries bit 4**. Under bit 4 = store,
that is a contradiction — unless the *latch* writeback is a different mechanism from the
accumulator store. `-INDEX.md` independently records `lo12 ∈ {0x647, 0x687}` as "the biquad
non-multiply steps", so the reading that survives is:

> **bit 4 is specifically `mem[ptr] ← ACCUMULATOR`; the latch→memory writeback is named in
> `lo12`, not in `hi12`.** Corroborated by `212.2.00.000`, the plain store, whose `lo12` is
> `0x000` — the store needs nothing from `lo12` at all.

**This is a REPAIR, not a prediction**, and it is weaker than everything else in §4. It is
recorded because leaving it out would make the bit-4 result look cleaner than it is.

### 4.6 bit 7 (**SPECULATIVE**)

Bit 7 is set on `082 090 092 094 09A` (the LFO phase machinery), `880` (external DRAM),
`0A2 0A6`, `182 192`, `282 292 29A` — and clear on `102 104 202 204 212 012 000`. The measured
context is that the two idioms threading bit-7 words are the two *index-generating* ones:
`092.A.**.200 → 082.2.**.1C0 → 094.A.**.200` (phase accumulate → read → wrap, 29/29) and
`900.1.**.1D5 → 192.A.**.000 → 082.2.**.1C0 → C40.3.**.44C → A00.0.**.041 → 880.1.**` (the
interpolated-tap transaction, 35/35). **SPECULATIVE reading: bit 7 marks the address/index
domain rather than the audio-data domain.** I am not asserting it: `0x0A2`/`0x0A6` and
`0x282`/`0x292` were not traced, and the reading has no control that could fail.

## 5. TASK B — THE DATA POINTER'S ORIGIN

### 5.1 The constraint, and three negative searches (**MEASURED**)

The program runs once per sample; its state cells must be in the same place next sample. So over
one pass the pointer must **return** or be **reset**.

```
   O1  net-zero over the whole program, searching all 512 class subsets:
       38/38 only for the DEGENERATE subsets (classes 0 and 5 always have addr8 == 0)
       best non-degenerate: 27/38 for {3}
       with ALL classes counted: net delta ranges -87 .. +1149, ZERO in 0 of 38 images

   O2  does it return modulo a wrap?  best modulus M=3 at 16/38 (chance).
       M=256, the addr8 space: 0/38.

   O3  a hi12-bit gate ("only words with bit b move the pointer"), all 4096 masks x 2
       polarities: 38/38 only for the degenerate "no word moves the pointer".
```

**The pointer does not return. It must be reset.**

### 5.2 The reset is not in any body (**PROVEN BY CONSTRUCTION**)

```
   words with lo12 == 0x821 (ldptr) in the 38 body images : 0
   words with hi12 == 0x801 in the 38 body images         : {801.0.00.021: 1}
```

The one that exists is the **coefficient-cursor** reset, not a data-pointer load. And the
firmware builds `801.0.NN.821` at `LABEL_0387E6` as
`08 01 (A>>4)&0F ((A<<4)&F0)|8 21`, so `addr8 == A` exactly — an **absolute 8-bit address**. The
cold-boot capture shows those words arriving on the host-poke channel
(`transfer 5: 01 60 08 01 05 08 21` = `ldptr #0x50`; `transfer 7: … 08 01 06 E8 21` =
`ldptr #0x6E`), never in the `cmd 0x04` I-RAM instruction stream.

> **The brief's candidate "an explicit pointer load at program or section entry" is FALSIFIED:
> zero occurrences in 2974 words. `0x801` is a host write port, not a body instruction.**

### 5.3 The biquad is NOT an independent anchor (**CORRECTION**)

`-biquad-map.md` §7 gives "channel bases `0x40` (ch 0) and `0x54` (ch 1)". Those numbers are the
cumulative `addr8` walk taken from word 0 **with the origin assumed to be zero**
(`tools/kn5000_dsp_biquadmap.py`, `CURSOR 1`). They are origin-**relative** and cannot pin the
origin; reading them as absolute C-RAM addresses would double-count an assumption. Flagged
because it is easy to get wrong and the brief's phrasing invites it.

### 5.4 VERDICT

> **THE ORIGIN CANNOT BE PINNED FROM THE ROM ALONE.** Of the brief's four candidates, one is
> falsified (§5.2) and the other three — set by the header, a per-effect base written by the
> host, implied by the terminator — are **mutually indistinguishable on static evidence**,
> because none of them leaves a mark in the instruction stream. What is established is the
> *shape* of the answer: **the pointer is reset at program start to a per-unit base that the
> instruction stream never names**, and bit 10 (§3) is now a plausible carrier for that reset.
> **INFERRED, not measured.**

**What would settle it, ranked by cost:**

1. **Run the core for one sample period and watch the C-RAM/D-RAM address bus.** The first data
   access after the terminator names the origin directly. The device exists at
   `src/devices/cpu/upd6383/`; it is instantiated **disabled**. One number out.
2. **Sweep one host parameter and find which body word's operand changes.** T1 gives the absolute
   address; the body walk gives the relative one; the difference *is* the origin. Also needs a
   live core, but tolerates a much cruder one.
3. The datasheet (`-INDEX.md` backlog 6).

**The ready-made falsifier stays valid and stays unused**: any candidate origin must still
reproduce the phaser's 18 exact cancellations, the biquad's `+4` per-band walk with bases
`0x40`/`0x54`, and the reverb's stationary pointer. All three are **differences**, hence
origin-free — which is precisely why none of them can supply the origin. That symmetry is the
whole reason this task does not close on static evidence, and it is worth stating plainly rather
than grinding further.

## 8. Falsified, or explicitly not established

* **★ MY OWN HYPOTHESIS, MEASURED AND FAILED: bits 9/8 encode the accumulator operation**
  (bit 9 = `acc += P`, bit 8 = `acc ← P`). It is a natural reading of `0x202` = `mac`, and it is
  **wrong**: the biquad's `[5] 102.2.FF.687` also performs `acc += P` (`-semantics.md` §6) while
  carrying bit 8 and not bit 9, and `[8] 000.2.03.647` performs `acc ← P` with **no** bit set in
  `hi12` at all. Two different bit patterns for the same accumulator op, and the "load"
  op with none. **Bits 9:8 are a field (4/4 values observed) whose meaning is UNKNOWN.**
  A follow-up guess — that they select between two multiplier/accumulator latches, as the
  CDJ-500 block diagram's `MPLY` K/L inputs would allow — is **SPECULATIVE and untested**.
* **`hi12` names THE operation** — **FALSIFIED as stated.** `hi12 = 0x000` is 27.2 % of the
  corpus, spread over 26 distinct `lo12` values and three classes, and includes both the NOP and
  the biquad's `acc ← P`. `hi12` names *what the word does to memory and to control flow*;
  `lo12` still carries operand routing and at least some ALU work. The brief's inherited framing
  from `-axes.md` §2.5 was over-stated in exactly one direction, and I am correcting it rather
  than building on it.
* **bit 0 = "addr8 is an absolute immediate"** — **PROVEN BY CONSTRUCTION for `0x801` only.** Two
  values carry bit 0 (`0x801`, `0x80B`), both inside the bit-11 escape. As a general rule it is
  **SPECULATIVE**.
* **bit 7 = the address/index domain** — **SPECULATIVE** (§4.6), no control.
* **bits 6 and 5** — no reading attempted; bit 6 has only 4 values (`040 050 142 C40`).
* **The pointer origin** — **NOT ESTABLISHED**, and shown not to be establishable from the ROM
  (§5).
* **NOT ESTABLISHED — that bit 4's destination in a terminator is `mem[ptr]`.** The five
  `612.1.**.000` words carry bit 4 with a unit index in `addr8` (§4.3).
* **Nothing here was executed.** The core is still disabled; everything is static.

## 9. What this instrument is blind to

1. **The residue-closure p-value is not as clean as it looks.** The nine residues are the
   corpus's *common* ops, so they are not uniform draws and the `8.2e-14` is an upper bound on
   the evidence, not a measurement of it. §3.2 says so and falls back on the qualitative
   argument.
2. **The HD-1 closure null holds popcount fixed but not much else.** A set of 54 values drawn
   from *any* structured generator would beat a popcount-matched null. `z = +7.9` says "not
   arbitrary"; it does not by itself say "twelve independent enables". The completeness results
   (§2.3) and the residue closure (§3.2) are what carry that.
3. **The `origin` searches are only as good as their hypothesis space.** I searched class
   subsets, moduli and single-bit gates. A search over *which of the 54 `hi12` values* carry a
   pointer delta would have 54 free binary choices against 38 equations — it would succeed, and
   the success would mean nothing. I did not run it, for that reason.
4. **`0x082`'s two contexts were not separated.** It occurs 64 times: 29 preceded by `0x092`,
   35 by `0x192`, and it is followed by `0x094` in the first case and `0xC40` in the second.
   Those are two different idioms sharing a word, and I treated them as one when arguing bit 7.
5. **bit 4's "absence" control uses classes whose `addr8` meaning was established elsewhere.**
   It is not fully independent of the project's own prior labelling — though it is independent
   of anything derived from `hi12`.
6. **The five bit-4 predictions (`008 080 084 08A 28A`) are untestable against this corpus** by
   construction. They need another ROM.
7. **Only IC311 (`uPD6383GF`) is in scope.** DSP2 (MN19413, IC310) is a different chip with a
   different word size and none of this transfers.

## 10. What would close the remaining gaps, ranked

1. **Enable the core and take one address-bus trace.** It settles the pointer origin (§5.4),
   which converts every `addr8` in the corpus into an address, and it would falsify or confirm
   bit 4 directly by showing whether a bit-4 word writes. **Two open questions, one experiment.**
2. **Decode bits 9:8 and bits 3:1.** They are *proven* to be fields (§2.3) with unknown meanings,
   which is a much better-posed target than "the remaining vocabulary". The biquad section is the
   right probe because its dataflow is already determined word by word — my accumulator guess
   failed there, which means the section is sharp enough to falsify guesses.
3. **Separate `0x082`'s two idioms** (§9 item 4) and settle bit 7. Small and local.
4. **The datasheet** (`-INDEX.md` backlog 6). Everything in §2.6 marked "unknown" is one line of
   a pin/field table.
